Analyze Document Relations

Document 간 관계 분석 및 생성 (Step 3)

Args: doc_id: 분석할 Document ID (None이면 전체 문서 분석) top_k: 관련 문서 최대 개수 (기본: 4) text_weight: 텍스트 유사도 가중치 (기본: 0.4) graph_weight: 그래프 임베딩 유사도 가중치 (기본: 0.3) normalized_value_weight: NormalizedValue 공유 가중치 (기본: 0.3)

Flow: Step 1: /metadata/extract - 문서 추가 (text_embedding) Step 2: /graph/embeddings - 그래프 임베딩 생성 Step 3: /graph/relations/analyze - 관계 분석 ← 현재

Note: - 하이브리드 검색: 텍스트 임베딩 + 그래프 임베딩 + NormalizedValue 공유 - NormalizedValue 공유로 Key-Value 쌍의 실제 값 유사도 반영 - LLM으로 의미적 관계 추론 (SIMILAR_TO, EXTENDS, CONTRADICTS 등) - doc_id=null: 모든 문서에 대해 관계 분석 - 처리 시간이 오래 걸릴 수 있음 (문서 수 × top_k × LLM 호출)

Normalize Key Values

클러스터링 기반 Value 자동 정규화.

Args: key_name: 특정 Key명만 정규화 (None이면 전체 Key 정규화) similarity_threshold: 유사도 임계값 (0~1, 높을수록 엄격). 기본값 0.85 min_cluster_size: 최소 클러스터 크기 (작은 클러스터 무시). 기본값 2

Flow: 1. Key별로 연결된 모든 Value 조회 2. Value 간 유사도 행렬 계산 (RapidFuzz token_sort_ratio) 3. DBSCAN 클러스터링으로 유사한 Value 그룹화 4. 각 클러스터의 대표값 선정 (빈도수 높은 것, 동률이면 긴 것) 5. NormalizedValue 노드 생성 및 SAME_AS 관계 생성

Returns: 정규화 통계 (Key 수, 클러스터 수, 정규화된 Value 수)

Authorizations:
APIKeyHeader
Request Body schema: application/json
Key Name (string) or Key Name (null) (Key Name)
similarity_threshold
number (Similarity Threshold)
Default: 0.85
min_cluster_size
integer (Min Cluster Size)
Default: 2
